04 / Practical deployment design

The loop, not another app.

One task produces an individual benefit and an aggregate learning signal. Human decisions connect the two.

01

Enter through existing touchpoints

Public event QR, direct link or a link in a published video description. A lightweight Tamil/English web chat; no installation or account mandatory for the first interaction.

02

Create a real, measurable step

Choose a CV, mentorship, portfolio or apprenticeship-related next step; opt into follow-up separately. No party membership or political data needed.

03

Close the feedback loop

Participant reports progress or a barrier. A permitted coordinator can offer support or request confirmation. Distinguish self-report from independently reviewed evidence.

04

Surface aggregated patterns

Aggregate by public-service topic and delivery programme, not by voting intention. Leaders see completion denominators, missingness, resource use and recurring barriers.

05

Decide, test, measure again

Document decisions to add mentors, improve information or collaborate with existing providers; measure whether the intervention affected the barrier, not only total events.

Production architecture

Mobile web chat / PWA ↓ Authenticated civic case API ↓ Consent record · pseudonymous case ↓ Field task queue + evidence review ↓ Aggregated, de-identified signals ↓ TN Lens leadership decision brief

Centralised syncing is a future capability. This demo has no cloud case database or outreach automation.

Three deployment gates

  • Authority: check WTL's existing app and obtain the programme owner's approval; avoid parallel participant databases.
  • Privacy: separate contact details and follow-up consent from dashboards; access roles, deletion, audit records, escalation and human review.
  • Channel: do not assume WhatsApp Cloud API can be used by a political movement: Meta's WhatsApp Business Platform policy prohibits political parties, candidates and campaigns.
